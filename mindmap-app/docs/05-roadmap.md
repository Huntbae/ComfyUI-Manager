# 05. 개발 로드맵

원칙: **호환성 게이트를 먼저 통과한 뒤에 기능을 얹는다.**
예쁜 편집기를 먼저 만들고 나중에 XMind를 붙이면, 데이터 모델이 이미 굳어 있어 무손실 왕복이 불가능해진다.

---

## Phase 0 — 포맷 실측 (필수 선행) — 🟡 **부분 완료**

> **진행 상황**: 실제 `.xmind` 5개(252 토픽)로 스키마 실측·왕복 하네스·게이트 통과를 달성했다.
> 결과는 [07번 문서](07-corpus-measurement.md), 도구는 `tools/`.
> **남은 것은 마커·경계선·요약·말풍선을 쓴 샘플 확보뿐이다.**

| 항목 | 상태 |
|---|---|
| 샘플 코퍼스 | 🟡 5개 확보 / 목표 15~20개 |
| 스키마 추출기 | ✅ `tools/schema_extract.py`, `tools/topic_fields.py` |
| 왕복 하네스 | ✅ `tools/roundtrip.py` |
| 무편집 왕복 diff = 0 | ✅ 5/5 (**바이트 동등까지 달성**) |
| 마커 ID 목록 | ❌ 샘플 부족 |
| 경계선/요약/말풍선 형태 | ❌ 샘플 부족 |
| 다중 시트 · legacy 파일 | ❌ 샘플 부족 |
| XMind 앱 육안 검증 | ❌ 미실시 |

**목표**: [01번 문서](01-xmind-format.md)의 `[추정]`을 전부 `[확인]`으로 만든다.

| 작업 | 산출물 |
|---|---|
| 샘플 코퍼스 수집 | `fixtures/` — 실제 Xmind로 만든 15~20개. 기능별 1개씩 + 실사용 대형 맵 2~3개 |
| 스키마 추출기 | `tools/schema-extract` — 모든 JSON 경로와 타입을 집계 |
| 필드 사전 | `docs/xmind-schema.md` — 실측 기반 확정 스펙 |
| 마커 ID 목록 | 내장 마커 전체 ID → 우리 아이콘 매핑 테이블 |
| 왕복 하네스 | `unzip → parse → serialize → zip` 후 정규화 diff |

**완료 기준(게이트)**
- 코퍼스 전체에 대해 **무편집 왕복 diff = 0**
- 우리가 저장한 파일이 **실제 Xmind 앱에서 정상 렌더링** (육안 확인, 체크리스트 기록)

> ⚠️ 이 게이트를 통과하지 못하면 Phase 1로 넘어가지 않는다.
> 여기서 드러나는 문제는 나중에 고치면 10배 비싸진다.

**기간 감각**: 2~3주. 대부분 샘플 수집과 눈으로 대조하는 노가다다. 단축하려 하지 말 것.

## Phase 1 — 무손실 코어 (`packages/xmind-format`)

- `XMindReader` (modern + legacy 읽기)
- `XMindWriter` (preserve-and-patch)
- `ResourceStore` (이미지/첨부 + manifest 동기화)
- 다중 시트
- CI에 왕복 테스트 상시 실행

**산출물**: 독립 npm 패키지 (오픈소스 공개 검토)
**완료 기준**: 코퍼스 100% 왕복 무손실 + `xmind-generator` 출력과의 구조 동등성 테스트 통과

---

## Phase 2 — 최소 편집기 (MVP)

- `simple-mind-map` 통합 + 우리 Document Model 연결
- 노드 CRUD, 텍스트 편집, 드래그 이동, 접기/펼치기
- **Xmind 키맵**(Tab/Enter/Space) 그대로
- undo/redo (CommandBus)
- 노트 · 라벨 · 링크 · 이미지 · 마커
- 웹에서 File System Access API로 로컬 파일 직접 열기/저장
- 구조 전환 4종 (마인드맵 / 논리도 / 조직도 / 트리)

**완료 기준**: **"기존 .xmind를 열어 실제 업무 편집을 하고 저장해도 아무것도 깨지지 않는다."**
사내 도그푸딩 2주.

---

## Phase 3 — Xmind 동등 기능

- 요약 · 관계선 · 경계선 · 플로팅 토픽 **편집** (Phase 1에선 보존만)
- 타임라인 · 피시본 · 매트릭스 구조
- 테마 시스템, 브랜치 색상, 노드 스타일 패널
- **아웃라이너 뷰** (가성비 1위)
- 검색/필터, 미니맵
- Export: PNG / SVG / PDF / Markdown / OPML
- Import: Markdown / FreeMind / OPML

---

## Phase 4 — 데스크톱 & 완성도

- Tauri 패키징, `.xmind` 파일 연결, 최근 파일, 자동 저장 + 로컬 히스토리
- 대형 맵 성능 (뷰포트 컬링)
- 다크 모드, 접근성(키보드 전용 탐색, 스크린리더 라벨)
- 다국어 (ko/en)

---

## Phase 5 — 차별화 (선택)

우선순위는 **사용자 피드백을 받고 결정**한다. 후보:

| 후보 | 매력도 | 비고 |
|---|---|---|
| Pitch(슬라이드) 모드 | 중 | Xmind Pro 유료 기능. 무료로 주면 전환 유인 |
| AI 보조 (텍스트→맵, 브랜치 확장) | 상 | Claude API 등 연동. 로컬 우선 원칙과의 충돌 설계 필요 |
| 실시간 협업 (Yjs) | 중 | 서버 운영 비용 발생 → 비즈니스 모델 결정 후 |
| Git 친화 텍스트 포맷 | 상 | `.xmind` ↔ Markdown 양방향. 개발자 시장에 강력 |
| Obsidian / VSCode 플러그인 | 중 | 배포 채널 확보 |

## 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| **XMind가 포맷을 변경** | 치명 | preserve-and-patch 구조라 미지 필드는 자동 통과. 버전 감지 + 코퍼스 회귀 테스트로 조기 발견 |
| 공식 스펙 부재로 인한 오해석 | 높음 | Phase 0 실측 + `xmind-generator`(공식) 출력 대조 |
| `simple-mind-map` 업스트림 변화/중단 | 중간 | MIT라 포크 가능. **어댑터 계층으로 격리**해 교체 가능하게 유지 |
| 중국어 문서로 인한 온보딩 비용 | 낮음 | 어댑터 계층 인터페이스를 한/영으로 문서화 |
| 대형 맵 성능 | 중간 | Phase 4에서 뷰포트 컬링. Phase 0 코퍼스에 대형 맵 포함해 조기 측정 |
| 상표/트레이드드레스 분쟁 | 중간 | [06번 문서](06-legal-risk.md) 준수. 에셋 복제 금지, 아이콘 자체 제작 |
| 범위 폭주(Xmind 전 기능 추격) | 높음 | MoSCoW 고수. **Won't 목록을 매 스프린트 재확인** |
