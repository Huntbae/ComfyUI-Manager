# 시리즈 v3 — "전기차 만들기" (형식을 매편 바꾼다)

## 왜 바꿨나

v2까지 20편이 전부 같은 틀이었다. **질문 제목 → 도입 → 이론 앵커 → 설명 → 문의.**
스타일만 손대서는 해결되지 않는 문제라 글의 형식 자체를 편마다 다르게 가져간다.

주제도 옮겼다. 네이버 데이터랩 확인 결과 그동안 쓰던 말은 검색 수요가 사실상 없었다.

| 키워드군 | 검색량 지수 |
|---|---:|
| 전동카트 · 골프카트 · 전기차 만들기 | 100 (기준) |
| 방과후 코딩 · 메이커교육 · STEM | 4~15 |
| 사이클카트 · 전기 카트 · 뉴트로엠 | 4~14 |
| 에듀카트 · 교육용 전기카트 · 코딩 교육 키트 | 0.06 (12개월 중 11개월 집계 없음) |

그래서 **전기차 만들기**를 중심에 두고, 제품은 그 안에서 자연스럽게 나오게 한다.

## 구성 — 10편, 10가지 형식

| 편 | 형식 | 제목 | 사진 |
|---|---|---|---:|
| 01 | 입문 안내 | 전기차 만들기, 뭐부터 사야 하나 | 1장 |
| 02 | 사진 일지 | 전기차 한 대를 부품으로 다 펼쳐봤다 | 2장 |
| 03 | 현장 채집 | 처음 타본 사람들이 하는 말 | 3장 |
| 04 | 실패담 | 처음 만들 때 태워먹은 것들 | 2장 |
| 05 | 진단표 | 전기차가 안 움직일 때 — 5분 진단표 | 2장 |
| 06 | 역사·배경 | 100년 전에도 사람들은 차를 직접 만들었다 | 3장 |
| 07 | 비교 | 아두이노로 짤까, 완제품 컨트롤러를 살까 | 2장 |
| 08 | 단계 가이드 | 전기차 조립 순서 7단계 | 2장 |
| 09 | 체크리스트 | 사람이 타기 전에 — 안전 점검표 | 1장 |
| 10 | 활용 사례 | 만든 다음이 문제다 — 어디에 쓰나 | 3장 |

문체도 형식에 맞춰 다르다. 실패담은 1인칭 과거형, 진단표는 증상→확인→조치,
체크리스트는 □ 항목, 현장 채집은 따옴표 인용 중심.

## 이미지

- **사진 수가 편마다 다르다** (1~3장). 넣는 위치도 형식에 따라 다르다.
- 같은 이미지를 두 번 이상 쓰지 않는다. 10편 21장이 전부 서로 다르다.
- 편마다 다른 스타일(비율·톤·마감)을 입힌다. 프리셋은 `scripts/styles.py`.
- **사진마다 설명을 붙인다.** 마커에 `|` 뒤로 적으면 사진 아래 한 줄로 들어간다.

```
[[img:edukart_02.png|카트 한 대를 분해해 바닥에 늘어놓은 모습]]
```

네이버 캡션 입력창은 자동화가 불안정해 본문 문단으로 넣는다.
블로그에서 흔한 형태이고 읽는 데 문제없다.

### 카드뉴스가 아니라 사진으로

카드뉴스(글자가 얹힌 디자인물)를 본문에 넣으면 광고처럼 보인다. 두 가지로 막는다.

- 수집 단계에서 `카드뉴스`·`상세페이지`·`표지`·`시안` 등을 제외 목록에 넣었다.
- 그래도 카드가 들어오면 **안에 박힌 사진만 잘라낸다.** 배경이 단색이고 글자 줄은
  배경과 다른 픽셀 비율이 낮다는 성질로 사진 영역을 찾는다. 일반 사진은 건드리지 않고,
  사진이 아예 없는 CTA 카드는 후보에서 뺀다.

```
python3 scripts/rebuild_images.py --dry-run        # 계획만 확인
python3 scripts/rebuild_images.py                  # 구글 드라이브에서 수집
python3 scripts/rebuild_images.py --no-sweep       # 제품 사진만 (전체 훑기 끔)
python3 scripts/rebuild_images.py --from-existing  # 드라이브 없이 기존 사진으로 (임시)
python3 scripts/rebuild_images.py --src ~/어떤폴더    # 검색 폴더 직접 추가
```

### 어디서 찾나

한 곳만 보지 않는다. 실행하면 검색할 폴더 목록을 먼저 출력한다.

| 대상 | 경로 |
|---|---|
| 내 드라이브 | `~/Library/CloudStorage/GoogleDrive-*/내 드라이브` |
| 공유 드라이브 | `.../공유 드라이브` (또는 `Shared drives`) |
| 공유 문서함 | `.../공유 문서함` (또는 `Shared with me`) |
| 로컬 작업폴더 | `~/Work Files`, `~/Documents/Work Files` 등 |
| 직접 지정 | `--src <경로>` (여러 번 사용 가능) |

계정이 여러 개면 계정마다 세 갈래를 모두 본다. 한글·영문 폴더명 둘 다 인식한다.
`내 드라이브/Work Files/클랜헌트` 처럼 드라이브 안에 있는 작업폴더는 내 드라이브를 돌 때 함께 잡힌다.

### 사진을 찾는 3단계

제품 사진이 모자랄 때 단계적으로 범위를 넓힌다. 앞 단계로 채워지면 다음 단계는 실행하지 않는다.

| 단계 | 범위 | 예 |
|---|---|---|
| 1단계 정밀 | 파일명·폴더명이 제품과 직접 맞는 것 | `에듀카트 v4.jpg`, `개발 차량 이미지/` |
| 2단계 확장 | 활동·부품 키워드 | `안전정비 교육`, `조립 워크숍`, `시승 체험` |
| 3단계 전체 | 드라이브 전체 사진 중 품질 통과분 | 최근 파일부터, 가로 800px·120KB 이상 |

모든 단계에서 공통으로 걸러내는 것:

- **서류·행정** — 실측확인서, 제원표, 견적, 계약, 공고, 입찰, 증빙, 정산
- **판촉물·화면** — QR코드, 현수막, 배너, 포스터, 명함, 스크린샷, 로고
- **개인정보** — 주민·여권·신분증·통장·이력서·서명·도장 등이 이름에 든 파일
- **상대 제품** — 에듀카트 자리에 칼리 사진이 들어가지 않게 서로 막는다
- **품질 미달** — 아이콘·썸네일·극단적 가로세로비

3단계로 뽑힌 사진이 있으면 실행할 때 목록과 함께 경고가 뜬다.
제품과 무관한 사진일 수 있으니 반드시 확인하고, 원치 않으면 `--no-sweep`을 쓴다.

`--from-existing`은 원본 사진이 모자라 같은 사진이 다른 스타일로 반복된다. 임시 방편이다.
제대로 하려면 드라이브 수집을 쓰고, eDu Kart Ver.5 사진은 `images_src/edukart_v5/`에 넣는다.

`node index.js next`는 실행 전에 사진 존재를 확인한다. 하나라도 없으면
사진 없이 글만 올라가는 것을 막고 멈춘다.

## 사실 범위

출처는 드라이브의 **`에듀카트 상세스펙.pdf`(클랜헌트&EMTRA)**. 여기 적힌 것만 쓴다.

| 항목 | 값 |
|---|---|
| 제어 보드 | **아두이노 메가** (자체 제작 Mega shield 제어용 회로 24V용) |
| 모터 | 24V 450W (48V 모터로 튜닝 가능 — 레이싱 대회용) |
| 모터 컨트롤러 | 12~48V 호환 |
| 배터리 | 리튬 배터리 24V 20Ah, 정격 24V (21~29.4V) |
| 속도 | 약 10km/h |
| 하중 | 120kg 내외 |
| 크기·중량 | 1725×770×810mm, 공차 중량 약 45kg |
| 바퀴 | 41cm |
| 전장 부품 | 키 스위치, 기어 스위치, 7세그먼트 모듈, LED 4, 메인 차단기, 쓰로틀 2(엑셀·브레이크), 하네스 |

스펙 문서에 없어서 쓰지 않는 것: 모터·드라이버 모델명(BTS7960·MY1020Z 등),
배터리 화학 계열(LiFePO4 등), 가격, 충전시간, 주행거리, A/S 정책.

**확인이 필요한 항목** — 아래는 이 스펙 문서에 없다. 이전 product_brief에서 가져온 것이라
근거를 다시 확인하기 전까지는 새 글에 쓰지 않는다.

- Ver.5 부품 절반·조립시간 60% 감소·커넥터 2종 통일
- 소프트스타트, 저전압 차단

스펙 문서에는 "단, 버전 및 모델에 따라 사양은 변동될 수 있음"이 붙어 있다.
버전이 갈리면 그 버전의 문서를 근거로 삼는다.

칼리는 1950년대 클래식·사이클카트 계보·전기구동·뉴트로엠(New Retro Mobility)·
삼족오 엠블럼·칼리/달리 캐릭터·가라지클럽.
