# 시리즈 v2 — "질문에서 출발하는 20편"

## 편집 방향

v1(36편, `articles_v1/`에 보관)은 제품 기능을 한 편씩 소개하는 구성이었다.
v2는 **독자가 실제로 던지는 질문**을 제목으로 삼고, 그 답에 이론 하나를 앵커로 얹는다.

- 제목 = 질문. 스펙 나열이 아니라 의사결정에 필요한 답을 준다.
- 각 편에 이론·학술 앵커 1개. 개념 이름과 제안자를 밝히고, 곧바로 제품 맥락으로 되돌아온다.
- eDu Kart(교육기관)와 칼리(공간·브랜드)를 홀짝으로 번갈아 배치해 두 독자층을 매일 번갈아 만난다.
- 사실·수치는 기존 확정 범위 안에서만 사용한다. 가격·충전시간·주행거리·A/S 정책 등
  확인되지 않은 값은 쓰지 않고, 필요한 경우 "문의" 또는 "고려할 항목"으로 처리한다.

## 이미지

각 편에 사진 2장을 `[[img:파일명]]` 마커로 본문 흐름 중간에 배치한다.
**같은 이미지를 두 번 이상 쓰지 않는다** — 20편 × 2장 = 40장이 모두 서로 다르다.

사진은 맥에 마운트된 구글 드라이브에서 직접 수집한다.

```
python3 scripts/rebuild_images.py --dry-run   # 무엇을 쓸지 확인만
python3 scripts/rebuild_images.py             # 수집 + 마커 재배정 + 검증
```

- eDu Kart 편(홀수)은 에듀카트 Ver.4/Ver.5 계열 사진 → `edukart_01~20.png`
- 칼리 편(짝수)은 칼리·뉴트로엠 계열 사진 → `kalli_01~20.png`
- 서류 스캔·도면·QR 등은 파일명으로 자동 제외

### 규격·톤 통일

출처가 제각각인 사진이 한 시리즈처럼 보이도록 40장을 같은 규격·같은 톤으로 맞춘다.

- **810×608 (4:3)** 한 규격. 잘려나가는 양이 25% 이하면 중앙 크롭,
  그보다 크면 자르지 않고 축소해 넣고 가장자리 평균색으로 여백을 채운다.
  카드뉴스처럼 글자가 든 세로 이미지의 제목·푸터를 잘라먹지 않기 위한 기준이다.
- **톤**: 대비 +6%, 채도 −6%, 밝기 +2%. 필터 티가 나지 않는 선에서 통일감만 준다.
- 손대고 싶지 않으면 `--no-style`을 주면 가로폭만 맞춘다.
- Pillow가 있으면 쓰고, 없으면 macOS `sips`로 넘어간다(이 경우 톤 보정은 생략).
- 기존 `images/`는 `images_prev/`로 보관되고, 마커는 수집 결과에 맞춰 다시 쓰인다
- 실행 끝에 "파일 존재 + 중복 사용 0건"을 자체 검증한다

Ver.5 사진을 따로 갖고 있으면 `images_src/edukart_v5/`에 넣어두면 우선 사용된다
(`images_src/`, `images_prev/`는 git에서 제외).

## 운영

```
node index.js next      # 다음 미게시 1편을 임시저장
```

진행 기록은 `.auth/progress.json`에 파일명으로 남는다. v1 파일명과 겹치지 않으므로
기존 기록이 남아 있어도 v2 20편이 처음부터 순서대로 나간다.
